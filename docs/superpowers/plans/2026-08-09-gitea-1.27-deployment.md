# Gitea 1.27 Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy Gitea 1.27.1 on `gitea.lab.canhdinh.com` with PostgreSQL 18, iDrive e2 object storage, SMTP, lego-managed built-in HTTPS on port 443, and no Gitea SSH transport.

**Architecture:** A two-play `gitea.yaml` first provisions a dedicated PostgreSQL login role and database, then applies a reusable Gitea role followed by the existing lego role. The Gitea role owns the verified binary, configuration, systemd service, temporary TLS seed, and administrator bootstrap; lego atomically replaces the temporary identity and gracefully reloads Gitea.

**Tech Stack:** Ansible 14.2, ansible-core, Debian 13, Gitea 1.27.1, PostgreSQL 18, community.postgresql 4.2.0, community.sops 2.4.0, systemd, GPG, OpenSSL, lego 5.3.1, Cloudflare DNS-01, iDrive e2 S3-compatible storage, SOPS 3.13.3.

## Global Constraints

- Target application host is `gitea.lab.canhdinh.com`; database host is `postgres.lab.canhdinh.com`.
- Pin Gitea to exactly 1.27.1; do not dynamically install an unreviewed `latest` release.
- Verify the detached GPG signature before replacing `/usr/local/bin/gitea`.
- Pin release-key fingerprint `7C9E68152594688862D62AF62D9AE806EC1592E2`.
- Serve built-in HTTPS only on port 443 with TLS 1.2 or newer and lego certificate paths.
- Do not create an HTTP redirect listener or reverse proxy.
- Disable Gitea SSH while leaving host administrative SSH unchanged.
- Connect to PostgreSQL with SCRAM-SHA-256 and `SSL_MODE = verify-full`.
- Use current Gitea 1.27 configuration keys and reject deprecated options in render tests.
- Keep custom Git hooks and local-path imports disabled.
- Disable registration, require sign-in, and create `gitea-admin` / `gitea-admin@canhdinh.com` only when absent.
- Store generated credentials in SOPS; never print or stage plaintext secrets.
- Keep Git repositories on the Gitea host; automated repository backup remains out of scope and must be documented.
- Do not modify the generic `lego` role unless a failing test proves a generic defect.
- Do not revert the user's existing `gitea_s3_bucket` or other SOPS edits.
- Do not commit any checkpoint unless the user explicitly authorizes commits.

```sh
for key in \
  gitea_database_password \
  gitea_secret_key \
  gitea_internal_token \
  gitea_lfs_jwt_secret \
  gitea_admin_password
do
  if ! sops --decrypt --output-type json group_vars/all/secrets.sops.yaml |
    SECRET_KEY_NAME="$key" python -c 'import json, os, sys; data = json.load(sys.stdin); value = data.get(os.environ["SECRET_KEY_NAME"]); raise SystemExit(0 if isinstance(value, str) and len(value) == 64 else 1)'
  then
    openssl rand -hex 32 |
      sed 's/^/"/; s/$/"/' |
      sops set --value-stdin group_vars/all/secrets.sops.yaml "[\"$key\"]"
  fi
done
```

mv -f "$NEW_KEY" "$DST_KEY"

- [ ] **Step 2: Implement PostgreSQL provisioning**

Use this exact order:

```yaml
- name: Install PostgreSQL Python adapter
  ansible.builtin.apt:
    name: python3-psycopg
    state: present
    update_cache: true

- name: Create Gitea PostgreSQL login role
  community.postgresql.postgresql_user:
    name: "{{ gitea_database_user | default('gitea') }}"
    password: "{{ gitea_database_password }}"
    role_attr_flags: LOGIN,NOSUPERUSER,NOCREATEDB,NOCREATEROLE,NOINHERIT,NOREPLICATION
    state: present
  become: true
  become_user: postgres
  environment:
    PGOPTIONS: -c password_encryption=scram-sha-256
  no_log: true

- name: Create Gitea PostgreSQL database
  community.postgresql.postgresql_db:
    name: "{{ gitea_database_name | default('gitea') }}"
    owner: "{{ gitea_database_user | default('gitea') }}"
    encoding: UTF8
    template: template0
    state: present
  become: true
  become_user: postgres
```

Do not change PostgreSQL role, HBA, or networks. The local superuser can inspect
`pg_authid`, allowing SCRAM comparison; do not use `no_password_changes: true`
or hide actual drift with `changed_when: false`.

   no redirect following, accepted codes `[200, 303]`.

openssl s_client -connect gitea.lab.canhdinh.com:443 \

- [ ] **Step 2: Implement idempotent administrator creation**

```yaml
- name: List Gitea administrators
  ansible.builtin.command:
    argv:
      - "{{ gitea_binary_path }}"
      - admin
      - user
      - list
      - --admin
      - --config
      - "{{ gitea_config_path }}"
  become: true
  become_user: "{{ gitea_user }}"
  environment:
    USER: "{{ gitea_user }}"
    HOME: "{{ gitea_home }}"
    GITEA_WORK_DIR: "{{ gitea_work_directory }}"
  register: gitea_admin_list
  changed_when: false

- name: Create initial Gitea administrator
  ansible.builtin.command:
    argv:
      - "{{ gitea_binary_path }}"
      - admin
      - user
      - create
      - --username
      - "{{ gitea_admin_username }}"
      - --password
      - "{{ gitea_admin_password }}"
      - --email
      - "{{ gitea_admin_email }}"
      - --admin
      - --must-change-password=true
      - --config
      - "{{ gitea_config_path }}"
  become: true
  become_user: "{{ gitea_user }}"
  environment:
    USER: "{{ gitea_user }}"
    HOME: "{{ gitea_home }}"
    GITEA_WORK_DIR: "{{ gitea_work_directory }}"
  when: gitea_admin_list.stdout is not search(gitea_admin_username)
  changed_when: true
  no_log: true
```

Import `admin.yaml` after the service starts. Never reset the password on
reruns; first-login password changes must not create drift.
